# Lot UI-002 — Événements et administration municipale : livraison

Le Design System UI-001 reste la source de vérité. Ce lot y ajoute 4 composants et 3 évolutions additives, toutes marquées **proposition à valider**. Aucun composant existant n’a changé de rendu ni de comportement par défaut.

| Livrable du brief | Où le trouver |
|---|---|
| 8 écrans, desktop / tablette / mobile | `prototype/templates/*.html.twig`, rendus dans `dist/prototype/` (visionneuse 375 / 768 / 1440, rangée « UI-002 ») |
| États alternatifs | Tableau « États » ci-dessous ; boutons « État » de la visionneuse (`?etat=chargement`, `vide`, `erreur`, `sans-zone`) |
| Interactions | Tableau « Interactions » ci-dessous ; simulation dans `prototype/proto.js` (hors design system) |
| Composants réutilisés / nouveaux | Sections « Composants » ; fiches `docs/components/{Stepper,SubNav,ZoneMap,Lifecycle}.md` |
| Données nécessaires au rendu Twig | Section « Contrat de données » ; valeurs fictives dans `prototype/data.mjs` |
| Points non tranchés | `docs/sections/etats-et-arbitrages.md`, points 23 à 41 |

Les gabarits n’appellent aucune route ni aucun service Symfony : toutes les URL et tous les textes métier arrivent en variables. Les droits, la validation, les transitions d’état et l’audit restent côté serveur ; le prototype les simule.

## États (brief, §états)

| État demandé | Où le voir |
|---|---|
| Chargement | `?etat=chargement` sur les listes (squelette) et les tableaux de bord |
| Liste vide | `?etat=vide` sur Événements et Utilisateurs ; onglets vides du tableau de bord ; « Désactivées » quand aucune zone |
| Erreur | `?etat=erreur` : liste non chargée (Réessayer) ; formulaire non enregistré (saisies conservées) |
| Confirmation | ConfirmPanel inline (suspension, clôture, désactivation, refus d’invitation) ; ConfirmDialog (activation, réactivation, annulation d’invitation, sortie avec saisie) |
| Accès non autorisé | `saumos/evenements.html`, `saumos/zones.html`, `saumos/utilisateurs.html` |
| Action indisponible | Bouton `unavailable_reason` : clôture bloquée, activation sans zone, désactivation de la zone permanente, dernière administratrice ; case de rôle désactivée avec raison |
| Succès | `?ok=…` : alerte focalisée en tête de page (ex. après suspension, invitation, création) |
| Événement suspendu / clôturé | Tempête — Hameau de Lauros / Pollution — Lagune de la Sablière |

## Interactions

| Situation | Comportement |
|---|---|
| Continuer dans l’assistant | Validation (serveur, simulée) ; erreurs résumées et reliées aux champs ; brouillon conservé ; retour aux étapes franchies par le Stepper ou « Modifier » du récapitulatif |
| Activer | Récapitulatif + conséquences ; ConfirmDialog ; si aucune zone : bouton indisponible avec la raison et un lien vers l’étape 2 |
| Quitter un formulaire modifié | « Quitter sans enregistrer ? » (cp--unsaved-guard, textes réglés pour UI-002) |
| Suspendre un événement | ConfirmPanel inline : conséquences, ce qui ne change pas, motif obligatoire |
| Réactiver | ConfirmDialog simple, sans motif, inscrit à l’historique |
| Clôturer globalement | Indisponible tant qu’une participation n’est pas clôturée (communes nommées) ; sinon ConfirmPanel « Clôturer définitivement » |
| Inviter une commune | Choix abonnée / non abonnée ; liste des abonnées non encore invitées, ou nom + e-mail de contact ; statut « Invitée — inscription à valider par CWS » |
| Répondre à une invitation | « Accepter et participer » (ConfirmDialog) ou « Décliner… » (message facultatif) |
| Modifier une zone utilisée | Avertissement : les événements gardent leur version ; « Utilisée par » indique la version de chaque événement |
| Modifier des rôles | Cases cumulables avec description ; le rôle administrateur de la dernière administratrice active est verrouillé, raison écrite |

## Composants

**Réutilisés sans changement :** AppShell, ContextSelector, MobileMenu, Banner, Breadcrumb, PageHead, SectionHead, Tabs, KpiTiles, EventCard, DataTable, FilterBar, Select, SearchField, Field, Choice, Check, ErrorSummary, Alert, EmptyState, Skeleton, Toast, ConfirmDialog, ConfirmPanel, Panel, Facts, ActionMenu, StatusPill, Tag, Icon.

**Nouveaux (propositions) :**

- `Stepper` (`stepper.html.twig`) : progression de l’assistant ;
- `SubNav` (`subnav.html.twig`) : rubriques d’un événement, en liens de page ;
- `ZoneMap` (`zone_map.html.twig`) : aperçu SVG en lecture seule, état « aucun tracé » ;
- `Lifecycle` (`lifecycle.html.twig`) : Brouillon → Actif ⇄ Suspendu → Clôturé.

CSS dans `src/css/components/events.css`.

**Évolutions additives (propositions, rétrocompatibles) :**

| Composant | Ajout | Pourquoi |
|---|---|---|
| Button | `unavailable_reason`, `id` | Le brief interdit de masquer une action sensible par une simple désactivation : le bouton reste focalisable et sa raison est écrite et annoncée. |
| Timeline | `detail: [{ label, before, after }]` par item | Historique des modifications avec l’ancienne et la nouvelle valeur (paramètres d’un événement, zones, rôles). |
| `cp--unsaved-guard` | valeurs `title`, `message`, `confirm`, `cancel` | Les textes UI-001 parlent de « décision » et de « dossier ». Les valeurs par défaut sont inchangées. |

Les mises en page propres aux écrans (`proto-split`, `proto-recap`, `proto-action`…) sont dans `prototype/proto.css`. Elles sont à reprendre dans les gabarits de page Symfony. Ce ne sont pas des composants du design system.
